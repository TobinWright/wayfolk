## About

Wayfolk (earlier called Idle Realm) ran live until November 2026. This is its full source, released under the MIT license so you can run your own world, learn from it or build on it.

**In the game:** hire heroes and send them out to gather, craft, explore and fight across one shared world map. Players trade on a market, form parties and guilds, chat, race slimes, play table games and climb seasonal leaderboards. Heroes keep working while you're signed out.

| | |
| --- | --- |
| **Client** | TypeScript, [PixiJS 7](https://pixijs.com) and webpack. Nearly all the art is drawn in code (`client/src/art/`) or generated by scripts (`client/tools/`) |
| **Server** | Node.js and TypeScript over WebSockets ([ws](https://github.com/websockets/ws)), with MySQL |
| **Shared** | `shared/` holds the game rules and message definitions both sides use |

> [!NOTE]
> **Music and sound effects aren't included.** They were licensed for the original game only. The game runs silently without them. To add your own, see [client/dist/assets/audio/README.md](client/dist/assets/audio/README.md).

## 📋 What you need


- **Node.js 20 or newer** (and npm)
- **MySQL 8** (MariaDB isn't tested; the schema uses MySQL 8's `utf8mb4_0900_ai_ci` collation)
- **Git**
- For a live server: a Linux box (Ubuntu 22.04/24.04 is what it ran on; 1 CPU and 2 GB RAM is plenty), a domain name, and nginx

## 💻 Run it locally (by hand)

### 1. Get the code

```sh
git clone <this repo's URL> wayfolk
cd wayfolk
```

### 2. Make the database

```sh
mysql -u root -p -e "CREATE DATABASE game_wayfolk CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci"
mysql -u root -p game_wayfolk < server/schema/schema.sql
mysql -u root -p game_wayfolk < server/schema/seed.sql
```

`schema.sql` makes the tables. `seed.sql` loads the travel graph (the map's nodes) and the cosmetic tiers.

### 3. Configure and start the server

```sh
cd server
cp .env.example .env        # then fill in DB_USER and DB_PASS
npm install
npm start                   # compiles in watch mode and restarts on changes
```

The server listens on **port 5301** (WebSocket and HTTP on the same port). Leave it running.

For a local game only the `DB_*` lines need filling in. Everything else (email, Google sign-in, Stripe, Sentry) stays off until it's configured. See [Settings](#-settings).

### 4. Build the client

In a second terminal:

```sh
cd client
npm install
npm run dev                 # webpack in watch mode: writes client/dist/bundle.js
```

A development build connects to `localhost:5301` by itself.

### 5. Serve the client and play

`client/dist` is a static site. Serve it with anything:

```sh
npx http-server client/dist -p 8080 -c-1
```

Then open **http://localhost:8080/** and press **Play as guest**.

If you serve it from another address (for example Apache/XAMPP at `http://localhost/wayfolk/client/dist/`), set `PUBLIC_URL` in `server/.env` to match. Email links and Stripe's return page use it.

### 6. Make yourself an admin (optional)

Sign in once, then:

```sql
UPDATE player SET role = 3 WHERE display_name = 'YourName';   -- 1 moderator, 2 editor, 3 admin
```

Sign in again and the admin menu appears. It includes a map editor and tools for players, reports and announcements.

## 🤖 Run it locally with AI

An AI coding agent such as [Claude Code](https://claude.com/claude-code) can do the whole local setup for you. Open a terminal in the cloned folder, start the agent, and paste in this prompt:

```text
Set this project up to run locally. Read README.md first.

I have MySQL running. Ask me for the root password when you need it; don't guess.

1. Create the game_wayfolk database from server/schema/schema.sql, then seed.sql.
2. Make a dedicated MySQL user for the game (not root) and write server/.env from
   .env.example with its details.
3. Install client/ and server/, start the server and the client's watch build,
   and serve client/dist.
4. Tell me the address to open.
5. Once I've signed in, make my account an admin.
```

> [!TIP]
> - **Read what it proposes** before approving, especially anything touching MySQL users or passwords.
> - **Keep secrets out of the chat** where you can. Let it write `.env` with placeholders and fill in the passwords yourself.
> - **If something fails**, paste the error back and ask it to explain the cause before it changes anything.

When you're ready to change the game, point the agent at [DESIGN.md](DESIGN.md). It describes every system and where its code lives, for example:

```text
Read DESIGN.md's section on fights, then make bosses drop twice the gold.
```

## 🌍 Run it live (by hand)

This is how the original ran: one Linux box with nginx in front (TLS, static files, WebSocket proxy), the Node server under systemd, and MySQL on the same machine. Ready-made configs are in [deploy/](deploy/). They assume the code at `/srv/wayfolk`, a `wayfolk` user, and the domain `example.com`.

> [!IMPORTANT]
> Replace `example.com` with your domain everywhere it appears, in the commands below and in `deploy/`.

### 1. The box

```sh
# as root, on a fresh Ubuntu
apt update && apt install -y nginx mysql-server git certbot python3-certbot-nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs
adduser --system --group --home /srv/wayfolk wayfolk
ufw allow OpenSSH && ufw allow 'Nginx Full' && ufw enable    # port 5301 stays closed: only nginx reaches the game
```

### 2. The code

```sh
sudo -u wayfolk git clone <this repo's URL> /srv/wayfolk
```

### 3. The database

```sh
mysql -e "CREATE DATABASE game_wayfolk CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci"
mysql game_wayfolk < /srv/wayfolk/server/schema/schema.sql
mysql game_wayfolk < /srv/wayfolk/server/schema/seed.sql
mysql -e "CREATE USER 'wayfolk'@'localhost' IDENTIFIED BY '<a long random password>';
          GRANT ALL ON game_wayfolk.* TO 'wayfolk'@'localhost';"
```

> [!CAUTION]
> Never copy a development database to the live server. It may hold test accounts.

### 4. `server/.env`

Copy `server/.env.example` to `/srv/wayfolk/server/.env` and set at least:

```ini
DB_USER=wayfolk
DB_PASS=<the password above>
TRUST_PROXY=1                       # nginx is in front
PUBLIC_URL=https://example.com/
MAP_EDITING=0                       # paint the map locally and deploy it instead
LOG_FORMAT=json
```

Then lock the file down: `chown root:wayfolk server/.env && chmod 640 server/.env`.

Add email (`SMTP_*`, `MAIL_FROM`) so password resets work. Google sign-in, Stripe, Sentry and the stats page are optional. See [Settings](#-settings).

### 5. nginx and HTTPS

```sh
cp /srv/wayfolk/deploy/nginx/wayfolk.conf /etc/nginx/sites-available/wayfolk
cp /srv/wayfolk/deploy/nginx/wayfolk-headers.conf /etc/nginx/snippets/
ln -s /etc/nginx/sites-available/wayfolk /etc/nginx/sites-enabled/
certbot certonly --nginx -d example.com -d www.example.com
nginx -t && systemctl reload nginx
```

nginx serves `client/dist` and passes `/ws` (the WebSocket), `/health`, `/stats` and `/stripe/webhook` to the game server on `127.0.0.1:5301`.

The security headers start as `Content-Security-Policy-Report-Only`. Play through the game with the browser console open, add anything it reports as blocked, then rename the header to `Content-Security-Policy`.

### 6. The game server under systemd

```sh
cp /srv/wayfolk/deploy/systemd/wayfolk.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now wayfolk
echo 'wayfolk ALL=(root) NOPASSWD: /usr/bin/systemctl restart wayfolk' > /etc/sudoers.d/wayfolk
journalctl -u wayfolk -f            # its log
```

### 7. Deploy

Write `/etc/wayfolk/deploy.env`:

```ini
APP_DIR=/srv/wayfolk
SERVER_IP=example.com
SERVER_PORT=443
SERVER_PATH=/ws
CLIENT_SENTRY_DSN=
```

Then, as the `wayfolk` user, run:

```sh
/srv/wayfolk/deploy/deploy.sh
```

It pulls the code, builds the server, **runs the tests (and stops if they fail)**, builds the client for your address, restarts the server and waits for `/health` to answer. Run it again for every update.

To do the same by hand:

```sh
cd /srv/wayfolk/server && npm ci && npx tsc -p . && npm test && npm prune --omit=dev
cd /srv/wayfolk/client && npm ci && npm run build -- --env SERVER_IP=example.com --env SERVER_PORT=443 --env SERVER_PATH=/ws
sudo systemctl restart wayfolk
```

A production build refuses to build for `localhost` or a missing address.

### 8. Backups (recommended)

[deploy/backup/](deploy/backup/) has a daily `mysqldump` uploaded with rclone, a systemd timer for it, and a script that test-restores the newest dump. The settings each one needs are listed at the top of each script.

### Every update

- Client and server always go out together: `shared/Routes.ts` numbers the messages by position.
- If a message's fields change without a route being added or moved, raise `PROTOCOL_BUMP` in `shared/Protocol.ts` so old clients reload.
- After changing tables, run `npm run schema` in `server/` (it dumps `schema/` from your dev database) and commit the result.

## 🤖 Run it live with AI

An AI agent can set up and deploy the server for you over SSH. There are two ways to do it.

**Option A: from your own computer.** Set up SSH key access to the box yourself first, so `ssh root@your-server` works without a password. Point your domain's DNS at the box. Then, from the project folder, give the agent this prompt, with your server and domain filled in:

```text
Deploy this game to my server, following README.md's "Run it live (by hand)".

- The box is reachable as: ssh root@<server>
- My domain is <domain>, already pointing at it.

Work over SSH. Show me each command before running anything that changes the
server, and replace example.com with my domain in the configs. Generate the
MySQL password on the server and write it straight into server/.env there,
without printing it. Ask me before enabling the firewall.

At the end, check that https://<domain>/health answers, and tell me what's
left that's optional (email, backups, Google sign-in).
```

**Option B: on the server itself.** Install the agent on the box, clone the repo, and run it there with the same prompt minus the SSH part.

> [!WARNING]
> **Check the firewall step yourself.** A wrong `ufw` rule can lock you out of SSH. Make sure `OpenSSH` is allowed before it's enabled.

> [!TIP]
> **Secrets stay on the server.** Ask the agent to generate passwords and keys on the box and write them into `.env` directly, never into the chat or the repo.

Prompts for later:

| When | Prompt |
| --- | --- |
| Deploying an update | *SSH in and run /srv/wayfolk/deploy/deploy.sh as the wayfolk user. If the tests fail, show me why and don't restart anything.* |
| Something's broken | *SSH in, read the last 200 lines of `journalctl -u wayfolk`, and explain what's failing before changing anything.* |

## 🔧 Settings

All settings are documented in [server/.env.example](server/.env.example). In short:

| Setting | What it does | Needed? |
| --- | --- | --- |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASS`, `DB_DATABASE` | MySQL connection | Yes |
| `PORT` | The game server's port (default 5301) | No |
| `TRUST_PROXY` | `1` behind nginx, so sign-in limits go by each player's address | Live |
| `PUBLIC_URL` | Where the client is served; used in email links and by Stripe | Yes |
| `SMTP_*`, `MAIL_FROM` | Sends password-reset and confirmation emails. Until set, they're written to the server log | Live |
| `GOOGLE_CLIENT_ID` | "Sign in with Google" (an OAuth web client ID). Empty: no Google button | No |
| `STRIPE_*` | The optional Premium subscription (see [PREMIUM.md](PREMIUM.md)). Off until set | No |
| `MAP_EDITING` | `1` lets admins paint the map in-game (writes into the repo's files); `0` on live | No |
| `STATS_KEY` | Turns on the analytics page at `/stats/` | No |
| `SENTRY_DSN` | Error reporting to Sentry | No |
| `LOG_FORMAT`, `LOG_LEVEL` | `json` for one JSON object per line | No |

Client build options are passed to webpack: `npm run build -- --env SERVER_IP=<host> --env SERVER_PORT=443 --env SERVER_PATH=/ws [--env SENTRY_DSN=...] [--env PREVIEW=1]`.

## 🎨 Make it your own

Some things still point at the original game. Change them for your own world:

- **The name and address:** `client/dist/index.html` (title and description), `client/tools/render-logo.js` (the logo; `npm run logo`), and `URL` in `client/src/components/demomode/DemoMode.ts`.
- **The Discord link:** `DISCORD_INVITE` in `client/src/constants/Constants.ts`.
- **The legal pages** in `client/dist/legal/` are templates. Fill in every `[[PLACEHOLDER]]` (operator, address, contact email and so on) before running a public server, and have them checked for where you live.
- **The world map** is `client/dist/assets/json/world.json` with the tilesets in `client/dist/assets/images/tilesets/`. Repaint it in-game with the admin map editor (`MAP_EDITING=1`). The original reference image the map was traced from isn't included, so `npm run world` (which rebuilds the tilesets and map from it) needs a reference of your own at `client/tools/reference/world-ref.png`. Your map-editor painting doesn't need it.
- **Sound:** see [client/dist/assets/audio/README.md](client/dist/assets/audio/README.md).

## 📁 Project layout

```
client/
  src/             the game client (components/ are the windows and screens, art/ draws the pixel art)
  dist/            the static site: index.html, css, assets, legal pages (bundle.js is built here)
  tools/           scripts that generate the world map, tilesets, logo and fonts
  art-source/      editable source for some images
server/
  src/             the game server (managers/ hold each system: heroes, fights, market, guilds, chat...)
  schema/          schema.sql and seed.sql, the database
  test/            unit tests and integration tests
  stats/           the optional analytics page
shared/            rules and message definitions used by both client and server
deploy/            nginx, systemd, deploy and backup scripts for a live server
DESIGN.md          design notes for every system, with where its code lives
PREMIUM.md         the optional Stripe subscription
```
